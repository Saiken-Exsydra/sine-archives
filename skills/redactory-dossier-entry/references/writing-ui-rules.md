# Writing And UI Rules

## Voice

Use archive-system language:

- Registry
- Dossier
- File
- Addendum
- Restricted
- Observation
- Index
- Seal
- Transmission
- Fragment

Avoid product language:

- Features
- Solutions
- Pricing
- Unlock
- Get started
- AI-powered
- Dashboard

## Readability

- Use clear section titles.
- Keep paragraph measure constrained.
- Provide enough spacing between dense lore blocks.
- Use tables only when comparison or file metadata benefits.
- Use warnings and annotations sparingly.

## Character Hero Copy

- `designation` is the character's short title, normally a 2-8 word noun phrase. It should express a specific role, contradiction, reputation, danger, promise, or organizing image.
- `summary` is a separate, understandable character statement, normally one sentence of roughly 15-35 words with a concrete role, action, belief, relationship, wound, choice, or consequence.
- Do not make the summary paraphrase the designation. The title creates curiosity; the sentence rewards it.
- Read the current dossier or controlling Archive source before writing either field. Preserve public spoiler boundaries and do not imply unsupported literal status through metaphor.
- Keep a strong existing pair. Specificity is the standard; compulsory rewriting and uniform mood are not.
- Apply the same dramatic identity and disclosure level in English and pt-BR, adapting rhythm naturally for each language.

## Canon Safety

- Do not invent new facts unless the user explicitly asks for expansion.
- If content is missing or ambiguous, preserve the ambiguity instead of filling it with generic lore.
- Prefer citations, cross-links, and existing archive references over new exposition.
